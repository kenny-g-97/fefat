# ADR-0021: Imports merge into the partitions they overlap

Decision log: [D-99](../masterplan/DECISIONS.md), 2026-11-14

## Context

A partition of the canonical store (ADR-0019) took one import: a contract's month of 1-minute bars, a contract's trade date of ticks. A later file with other rows for a partition the store held was refused whole, since "the first import stands" (D-49, D-50). So a download that continued a month already stored, an export that ended inside one, and a file that filled a session the first lacked could not come in, and the DBN importer, which wrote each partition as its file's clock passed it, could write a file's earlier months before a later month refused the file. Traders update a dataset with newer, older, and missing data as a matter of course (D-98).

What a merge may do is bounded by what the store already promises. A run pins its files by content (ADR-0009), a partition is replaced whole and in one step, and nothing in FEFAT removes a record once it is stored, so a wrong merge cannot be taken back. Prints stamped to the second share their instant with others, and a platform's export gives them no number to tell them apart by.

## Decision

- **Merging is the importers' default.** `import_databento` and `import_file` merge a file into the partitions it overlaps, without a flag.
- **A record's place** in a partition is its instant on the store's clock, `ts_open` for bars and `ts_recv` for everything else, and its position among the records of that instant, in stored or file order. A file's record at a place the store lacks is added, in clock order; one the store holds there with the same values in every column is already held, dropped and counted. A file that carries on an instant the store holds the start of adds the rest, and one that stops sooner in an instant adds nothing there.
- **Differing records.** An instant with a place the store holds with other values is disputed, and all the file's records at it differ. They refuse the file, nothing written, with their count and first trade date. An import told that the file's records stand (`differing=DifferingRecords.TAKE_THE_FILE`, `--differing take-file`) takes each disputed instant whole from the file, and the raw manifest records that the import was told so, whatever one run of it found to differ.
- **Refusals no option lifts,** since a merge cannot be taken back. A file whose records for a stored partition carry an `instrument_id` that partition does not hold, since one contract under two ids loads as two series. A file that overlaps a stored partition's records in time without a record at one of their instants, as prints stamped finer than a second are when they are read under another time zone or stamping rule, which a merge would store twice. Prints without a sequence of their own that dispute their file's first instant of a contract, or its last where the store holds more prints: the file may hold part of that instant alone, and taking it would drop stored prints it never held. And a file of a back-adjusted series the store holds that holds none of the store's bars unchanged: its platform adjusts such a series again at each roll, so that a later export moves every price before that roll, and without a bar the two share a file cannot be told from one adjusted since, whether its bars differ from the stored ones or only carry the series on.
- **Prints without a sequence of their own** are compared without it and numbered by their place in their instant, a print added to an instant the store holds numbered on from the stored prints' last, which keep their numbers. The number orders the prints of one instant (F-CLK-03) and says nothing else. Such a file starts on a whole instant; it may stop inside one.
- **Check, then write.** The whole file is read against the store before anything is written, so a refused file leaves the store as it was, the DBN importer included, which decodes its file a third time to write unless the file changes no partition. Everything that can refuse comes before the first partition: the reading, the datasets' unit and series, the refusals above, the differing records, and the verified copy of the original under `raw/`. The write stops at records that differ where the check refused them and so found none, since the store or the file then changed between the two. A partition that gains nothing is not written again, and a merged partition is written as one chunk, so that its bytes, and its hash, follow from its rows alone, whatever files it came in and whatever machine merged it: a sort leaves as many chunks as there are threads, which Polars writes as other bytes past one row group.
- **What stays.** Raw files never change, and each import's original is kept and recorded. A dataset's `dataset.json` is its first import's (D-11). One file is imported once, as its first import read it (D-50). A batch split into several DBN files is refused as one import; its files import one after another.

## Consequences

- A stored partition is no longer written once: each merge that adds to it gives its file a new hash. A snapshot that pinned the file refuses it (ADR-0019), so a saved run that read it cannot be explained or re-checked until it is run again, and its record and results stand; the refusal names the files written since the run, the dataset's `dataset.json` among them, as their times tell it, since a run's record keeps its snapshots' hashes alone.
- What reads the store notices by the same means as before: a clean quality report reads stale once a partition is newer than it (D-94); the engine's cache rebuilds the contract-months whose partitions' hashes changed; the features' cache computes again the partitions whose snapshots or roll calendar changed; and the roll calendar, one per dataset, is built again whole.
- A file that adds sessions before a dataset's first moves the anchor of its forward-anchored series (ADR-0007), as an import of older months always did: adjusted prices after it shift by the gaps of the added rolls, and every later cached feature is computed again. Raw prices and fills do not move.
- A merge only adds, or, where the file's records stand, replaces whole instants: a vendor's revision that drops a record is not applied, and nothing removes a record a wrong file added. The refusals and the default for differing records are what keeps such a file out.
- An import told that the file's records stand vouches for the file. Bars, and prints stamped to the second, read one bar or whole hours off land on the stored instants, so they pass the refusal of a file without a record at a stored instant and read as differing, almost none of them held: where the calendar check could not test a file's timing, the account of the merge is the last check before such records are taken.
- A source whose files of prints start inside an instant does not fit the place rule: where its first prints differ from the stored ones the file is refused, and where they equal them they count as held, so the prints of that instant the store lacks are not added.
- A back-adjusted series is brought up to date only by an export that holds a bar the store holds, unchanged, which shows that no roll moved the series between the two; such a file is left to the rule for differing records, so it completes a last bar the store took unfinished. An export made after a roll goes in whole, under a provider of its own. The rule also refuses an export of later months alone, which the importer took before this step on whatever price basis it came.
- Nothing locks an import: two at once into one dataset can lose one's records, which step 5.12 closes when imports run as jobs. An import cut short while it writes is finished by running it again, since the records it wrote read as held.
- The report of an import, and the previews of both importers, say per dataset what the file adds: the sessions new to their contract, the stored sessions that gain records, the records already held, and those that differ, in counts and dates alone. Step 5.12's wizard shows the same account before it writes.
- The code is `fefat.market.importers.partition_merge` (the rule), `partition_buffers` (the check, the tally, and the writes), `file_writer`, `databento`, and `file_import`.

## How we would know it is wrong

If a range imported as one file and as two files that overlap, in either order, left different rows in the store (the property test of step 5.14); if a quality report found duplicates, or a chart a doubled bar, at a join; if a refused file left a file behind; if an import told that the file's records stand stored a file read under the wrong time zone or bar stamping; if a source's files of prints started inside an instant, so that records the trader holds could not come in; if traders needed to remove or correct stored records without a newer file to take them from; or if routine updates refused saved runs so often that pinning whole partitions proved too coarse.

## Status

Accepted; recorded in step 5.14. It supersedes "the first import stands" (D-49, D-50) for a partition's records, which still holds for one file imported twice, and amends [ADR-0019](0019-canonical-market-data-store.md), whose partitions later imports now merge into.
